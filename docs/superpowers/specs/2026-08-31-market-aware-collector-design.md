# 会话感知行情采集与当日数据隔离设计

## 背景与根因

2026-08-31 启动监控后，页面把 2026-08-28 的收盘快照继续展示在“实时行情”中。现场证据如下：

- 系统时间为 2026-08-31，六个标的的页面时间均停在 2026-08-28 15:00。
- 沙箱身份可写运行目录，但无法连接东方财富 `push2his`；Windows 用户可连接数据源，却因运行目录 ACL 无法启动服务。
- 修正运行权限后，六个标的均成功取得 2026-08-31 的 241 个分钟点。
- 服务仍按 5 秒间隔在收盘后重复请求完整日线，随后出现 `schannel: server closed abruptly (missing close_notify)`，并由 `_publish_outage` 把本应为 `CLOSED` 的状态覆盖成 `OUTAGE`。
- 浏览器关闭或重连 SSE 时，服务端会把正常的 `ConnectionAbortedError` 输出为完整堆栈。

问题不是策略阈值，而是实时数据边界、生产者调度和错误语义混在一起：旧交易日行情可以进入实时视图，生产者不了解交易时段，采集失败又无条件覆盖市场状态。

## 目标

1. “实时行情”只展示上海时区当前自然日的分钟数据；旧交易日数据只能从历史日期入口查看。
2. 生产者根据交易日和连续交易时段决定是否采集，不在无新数据的时段持续请求。
3. 交易时段采集失败立即撤销候选并显示 `OUTAGE`；午休和收盘状态不被无关的采集错误覆盖。
4. 采集频率与分钟级数据相匹配，并对连续失败退避。
5. SSE 客户端正常断开不产生错误堆栈。
6. 不改变策略、回测、历史 schema v3、标的元数据或只读交易约束。

## 方案选择

### 方案 A：会话感知生产者与当日视图隔离（采用）

在现有单生产者内增加明确的交易会话策略；实时发布前过滤当前日行情；失败发布根据当前市场阶段决定状态。该方案直接修复数据与状态语义，测试边界清晰。

### 方案 B：只把刷新间隔调大

改为 60 秒能降低请求量，但旧日数据仍会进入实时页面，午休和收盘仍可能被失败覆盖为 `OUTAGE`，只能缓解症状。

### 方案 C：增加第二行情源或替换传输层

能降低单源故障概率，但会引入字段、复权、分钟边界和授权口径差异，也无法解决旧日数据泄漏及错误状态优先级。本次不采用。

## 详细设计

### 1. 交易会话策略

在 `market_data.py` 提供纯函数或小型不可变策略对象，根据上海时区时间、休市日历以及当前缓存日期返回以下阶段：

- `PRE_OPEN`：交易日 09:30 前。
- `MORNING`：09:30–11:30。
- `LUNCH_BREAK`：11:30–13:00。
- `AFTERNOON`：13:00–15:00。
- `CLOSED`：15:00 后、周末或日历休市日。

采集规则：

- `MORNING`、`AFTERNOON`：允许采集。
- `PRE_OPEN`：不采集，避免数据源返回上一交易日并被误认为当天数据。
- `LUNCH_BREAK`：缓存已有当天行情时暂停；若服务午间首次启动且没有当天行情，允许一次补采，然后暂停。
- 交易日 `CLOSED`：缓存已有当天行情时暂停；若服务收盘后首次启动且没有当天行情，允许一次补采收盘数据，然后暂停。
- 周末或日历休市日：不采集，不把上一交易日数据放进实时视图。

生产者仍只有一个线程。活动交易时段按分钟边界采集，基础间隔为 60 秒，不再每 5 秒重复下载完整当日分钟序列。连续失败使用 60、120、240、300 秒的有上限退避；成功后恢复 60 秒。停止事件必须能立即唤醒等待，保持现有安全关闭语义。

### 2. 当前日行情隔离

运行时加载或采集原始行情后，以 `generated_at` 的上海自然日作为实时会话日期：

- 每个标的只保留该日期的分钟点用于实时 engine、`/api/snapshot` 和 `/api/quotes`。
- 标的没有当前日分钟点时，实时视图按缺少当日行情处理，不显示旧价格、旧图表或旧指标。
- `/api/quotes?since=...` 的 reset 与增量都只能包含当前日、已完成、schema v3 的分钟点。
- 历史文件和按日历史接口不删除旧交易日数据，日期选择器仍可查看 2026-08-28 等历史记录。
- 一旦交易日期变化，服务发布权威 reset，客户端清空上一日分钟缓存后再接收新日数据。

页面在没有当前日数据时显示“暂无当日行情”，并保留明确的市场状态；不得用旧图形填充实时区域。

### 3. 失败与状态优先级

采集失败时重新读取当前上海时间：

- 活动交易时段：发布 `OUTAGE`，立即将候选降级为“偏离观察”，追加 `MARKET_NOT_REALTIME`，保留最近一次有效数据但明确标为非实时。
- 午休：发布 `LUNCH_BREAK`，不产生候选，不把预期的无更新解释为断流。
- 收盘、周末、休市日或盘前：发布 `CLOSED`，不产生候选。

只有活动交易时段的采集失败进入用户可见错误列表。非活动时段不会主动采集，因此正常情况下不会产生网络错误；如果在时段切换边界已有请求在途，其失败按完成时刻的市场阶段归类。

### 4. 传输层与请求频率

保留现有东方财富 `trends2` 解析、三次重试和 PowerShell 回退，不引入第二数据源。本次通过会话调度和退避降低请求压力，而不是放宽 JSON、代码、市场、OHLC 或量价校验。

启动脚本默认刷新配置改为 60 秒。README 明确说明：采集进程需要正常主机网络权限；若在受限沙箱中运行，健康接口会显示 `OUTAGE`，但不会把旧交易日数据伪装成实时数据。

### 5. SSE 正常断开

事件写入路径捕获 `BrokenPipeError`、`ConnectionResetError` 和 Windows `ConnectionAbortedError`，把它们视为客户端关闭或重连并结束当前连接。其他异常继续记录和传播，避免吞掉真实服务端错误。

## 数据流

1. 生产者读取时钟与交易日历，判断当前阶段和是否需要补采。
2. 允许采集时，collector 写入 staging，并完成现有适配与市场数据校验。
3. 原子替换正式快照、upsert 已完成分钟历史。
4. 发布前过滤当前上海自然日，engine 只评价当前日数据。
5. revision delta 仅携带当前日已完成分钟；跨日使用 reset。
6. 页面只渲染所选标的当前日分钟数据，历史入口独立读取历史文件。

## 测试与验收

采用 TDD，至少覆盖：

1. 新交易日以旧快照启动时，实时快照和分钟接口不返回旧日分钟点。
2. 交易日盘前不调用 collector。
3. 午间首次启动且无当天数据只补采一次；已有当天数据时不采集。
4. 收盘后以旧快照启动只补采一次；成功取得当天收盘数据后不再调用 collector。
5. 收盘后已有当天数据时，后台循环零采集并保持 `CLOSED`。
6. 活动交易时段失败立即变为 `OUTAGE` 并撤销候选。
7. 在途请求跨入午休或收盘后失败时，不覆盖 `LUNCH_BREAK` 或 `CLOSED`。
8. 连续失败按上限退避，成功后恢复基础间隔；停止线程无需等待完整退避周期。
9. 跨日 revision 触发权威 reset，客户端不保留昨日分钟缓存。
10. SSE 的三类预期断开异常不输出堆栈，其他异常仍可见。
11. 全量单元测试和纯 Git 归档测试全部通过。
12. 真实服务验证：六个标的日期一致为当天；收盘后健康状态为 `CLOSED`；页面无断流红条、无旧日实时图、控制台无错误。

## 非目标

- 不新增交易执行能力。
- 不调整候选阈值、趋势识别或回测逻辑。
- 不承诺秒级实时价；当前数据源和策略以完成分钟为决策粒度。
- 不在本次接入 Wind 或其它备用行情源。
- 不重写既有 Git 历史。

## 运维与回滚

所有改变局限在会话判断、运行时过滤、刷新调度、SSE 断开处理、启动默认值和相关文档。若上线后出现问题，可回退本次提交；schema v3 历史文件无需迁移。服务重启后从正式行情快照与历史文件恢复，staging 文件仍按现有规则清理。
