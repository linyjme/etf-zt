# 监控标的添加校验与反馈设计

## 背景与根因

添加接口目前先写入 `watchlist.json`，但不检查 `etf_metadata.json`。因此，缺少交易元数据的 `515180` 已被持久化；后台生产者在下一轮采集时拒绝该标的，将整个行情状态降为 `OUTAGE`，而快照仍只包含原有 6 个标的。页面成功路径又没有可见提示，所以用户看到输入框和列表没有明确变化，误以为点击无效。

## 目标

- 缺少交易元数据的代码不得写入监控列表，也不得影响现有标的行情健康。
- 添加成功和添加失败都必须在表单旁显示明确中文反馈。
- 保持单一后台行情生产者；HTTP 请求线程不直接采集行情。
- 清理本次已写入但不可运行的 `515180`，恢复当前 6 个标的的正常监控。

## 方案

### 后端事务边界

`MonitorApplication.add_watch_item` 在持有现有监控列表写锁时，先读取交易元数据并验证目标代码存在。验证顺序为：代码与名称格式、重复代码、交易元数据存在、原子写入。任何一步失败都不修改文件。

缺少元数据时抛出专用业务异常，请求处理器返回 HTTP `422`：

```json
{
  "error": "missing_metadata",
  "message": "缺少交易元数据，无法添加: 515180"
}
```

不根据代码前缀猜测交易所、涨跌幅、整手或日内回转规则，也不自动生成关联指数元数据。

### 页面反馈

表单增加独立的状态样式。提交期间禁用按钮；成功后清空输入并显示“已添加 CODE，等待下一轮行情刷新”；失败时保留输入并显示服务端中文原因。下一轮后台采集仍由现有单一生产者完成，避免并发写历史数据。

### 现有异常数据清理

从当前 `data/monitor/watchlist.json` 删除缺少元数据的 `515180`。这是对本次失败添加的回滚，不修改其他 6 个标的及其参数。

## 测试与验收

- 应用层测试：缺少元数据时拒绝添加，且监控文件字节不变。
- HTTP 测试：未知元数据返回 `422/missing_metadata` 和中文消息。
- 页面测试：成功路径显示成功反馈并清空表单；失败路径保留输入并显示后端消息。
- 回归测试：合法、重复、格式错误的原有行为保持不变。
- 运行验收：清理 `515180` 并重启或等待刷新后，`/health` 不再因该代码报告 `OUTAGE`；页面显示 6 项且原有行情继续刷新。

## 非目标

- 不新增或猜测 `515180` 的金融元数据。
- 不接入新的外部行情或基金档案服务。
- 不改变行情刷新周期、策略门控或回测逻辑。
