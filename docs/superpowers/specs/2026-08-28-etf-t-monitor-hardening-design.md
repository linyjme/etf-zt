# ETF 做T监控可靠性改造设计

日期：2026-08-28  
状态：已确认  
范围：行情采集与持久化、市场状态识别、候选信号、做T回测、Web 增量接口、运行状态、仓库卫生

## 1. 背景与目标

当前项目能够采集六只 ETF 的分钟行情、计算白黄线偏离、展示提醒并进行简单回放，但存在五类会直接扭曲结果的问题：

1. 历史文件采用 append-only 和 `symbol + timestamp` 去重，早期临时分钟会永久阻止最终分钟覆盖。2026-08-28 的 510300 历史因此保留了 4.095、4.106、4.128 三个模拟点，并与真实昨收 4.691 混合。
2. `UNCERTAIN` 未进入提醒屏蔽条件，页面可能同时显示“状态未知，暂停做T”和方向性“黄金窗口”。
3. `RANGE` 采用六项满足三项的软评分，未把双侧停留和 VWAP 穿越作为硬门槛，导致单边行情误判为震荡。
4. 配置文件使用一格 0.2%，但读取缺省值和新增标的使用一格 2%。
5. 现有回放从现金开始全仓买卖，没有底仓、T 仓、可卖库存、配对腿和相同底仓基准，本质上是长仓择时。

本次改造的目标是：先保证分钟数据可信，再让状态识别和候选提醒严格依赖可信的已完成分钟，最后使用真实库存约束评估做T相对“不操作底仓”的净增益。系统仍然只读监控，不接入或提交任何交易。

## 2. 已确认的设计决策

- 采用有限模块化重构，不引入数据库或异步 Web 框架。
- JSONL 继续作为可审计历史格式，但写入改为原子 upsert。
- 后台刷新线程是行情、历史、提醒和发布快照的唯一生产者；HTTP/SSE 请求只读。
- 实时快照可以展示当前未完成分钟，但状态识别、候选提醒和回测只使用已完成分钟。
- 唯一默认格宽为 `0.002`，即一格 0.2%。
- 候选提醒只在连续确认的 `RANGE` 中产生；其他状态只能观察或等待。
- 做T回测默认以 15,000 元折算初始底仓，T 仓上限为底仓的 20%，配置允许按标的覆盖。
- 六只现有标的是境内股票 ETF，均按 T+1 可卖规则记账。
- 当前未提交的 ETF—指数映射与指数估值模块属于现有用户工作，改造必须兼容并保留。

## 3. 模块边界

改造后各单元职责如下：

- `constants.py`：格宽、状态窗口、确认次数、成本、整手和回测默认值的唯一来源。
- `market_data.py`：交易时段、已完成分钟判断、行情健康状态、分钟交叉校验、schema v3 序列化和历史原子 upsert。
- `regime.py`：只接收同一交易日、同一连续交易时段的已完成分钟，输出状态、指标和连续确认数。
- `t_strategy.py`：根据行情健康、状态、偏离收窄和成本覆盖情况输出候选或观察结果，并列出全部屏蔽原因。
- `t_backtest.py`：库存、现金、订单成交、配对腿、基准账户和统计结果。
- `t_monitor.py`：保留公共模型与兼容门面，组合上述组件生成监控快照。
- `t_web.py`：后台单生产者、只读 API、SSE 增量发布和页面资源。

每个模块都通过不可变数据对象通信。Web 层不直接修改历史，回测层不重新实现信号逻辑，状态识别层不读取文件或系统时间。

## 4. 行情数据生命周期

### 4.1 已完成分钟

一个分钟点只有在 `observed_at >= timestamp + 1 minute` 时才被视为完成。实时文件可包含尚未完成的最后一分钟，但该点带 `is_complete = false`，不进入指标、候选或回测。

上午和下午是两个独立连续时段：09:30–11:30 与 13:00–15:00。窗口不能跨午休、跨交易日或跨越缺失分钟。11:30 与 15:00 的最终分钟只有在一分钟后观察到最终值时才进入历史。

### 4.2 分钟 schema v3

持久化记录至少包含：

```json
{
  "schema_version": 3,
  "symbol": "510300",
  "name": "沪深300ETF华泰柏瑞",
  "trading_date": "2026-08-28",
  "timestamp": "2026-08-28T09:30:00+08:00",
  "observed_at": "2026-08-28T09:31:05+08:00",
  "is_complete": true,
  "source": "东方财富 push2his trends2",
  "previous_close": 4.691,
  "open": 4.681,
  "high": 4.686,
  "low": 4.681,
  "price": 4.684,
  "average_price": 4.683,
  "volume": 12345,
  "amount": 5789012
}
```

主键是 `symbol + timestamp`。同键记录只有在新记录通过全部校验且 `observed_at` 更新时才覆盖旧记录。文件每次按主键排序后写入同目录临时文件，`fsync` 后原子替换；总历史与按日历史由同一组规范化记录生成，不能分别追加造成分叉。

### 4.3 数据校验

写入前逐标的、逐交易日执行以下校验：

- `trading_date` 必须等于带时区 `timestamp` 的上海日期。
- 同日所有分钟的 `previous_close` 必须在一个最小报价单位内一致。
- `price/open/high/low/average_price` 必须为有限正数，且 `low <= open, close <= high`。
- 价格相对昨收不能越过标的元数据的涨跌幅限制加一个报价单位。
- `volume` 与 `amount` 必须为有限非负数；一个为零而另一个显著非零时拒绝。
- `volume > 0` 时，使用元数据的成交量单位反算分钟成交均价；该价格必须落在 OHLC 区间附近。
- 时间必须严格落在交易时段，分钟序列不得倒序。

六只标的元数据增加 `exchange`、`asset_type`、`intraday_turnaround`、`sellable_delay_days`、`lot_size`、`price_tick`、`price_limit_pct` 和 `volume_unit_shares`。159915 与 588000 的涨跌幅限制按 20% 配置，其余四只按 10% 配置；六只均设置 `intraday_turnaround = false`、`sellable_delay_days = 1`、`lot_size = 100`、`price_tick = 0.001`。

### 4.4 单生产者

后台循环按以下顺序运行：

1. 拉取六只标的完整当日快照。
2. 解析并交叉校验。
3. 从实时记录中筛选已完成分钟。
4. 原子 upsert 历史。
5. 以已完成分钟计算状态、候选和提醒事件。
6. 生成递增 revision 的不可变内存快照。
7. 唤醒 SSE 客户端。

任何步骤失败都不会覆盖最后一份有效实时文件或历史；但发布状态会立即变为 `OUTAGE`，并清除旧候选。

## 5. 行情健康状态

健康状态使用上海时区、可配置休市日期、当前交易时段、最后成功采集时间和最后行情时间综合判断：

- `REALTIME`：连续交易时段内，最后行情年龄不超过 75 秒，且最近采集成功。
- `DELAYED`：连续交易时段内，最后行情年龄大于 75 秒但不超过 180 秒，且没有明确采集错误。
- `OUTAGE`：连续交易时段内有明确采集错误、缺少当日行情，或行情年龄超过 180 秒。
- `LUNCH_BREAK`：同一交易日 11:30 后至 13:00 前。
- `CLOSED`：收盘后、开盘前、周末或配置的休市日期。

快照同时提供 `quote_age_seconds`、`last_success_at`、`last_error_at`、`last_error` 和 `health_reason`。只有 `REALTIME` 允许候选；其他状态即使保留最后价格用于观察，也必须把 action 降为非方向性的观察或不可用。

## 6. 状态识别

### 6.1 输入窗口

状态窗口固定为最近 20 个已完成分钟，并要求分钟连续、属于同一交易日和同一上午或下午时段。窗口无效时状态为 `UNCERTAIN`，确认次数归零。

### 6.2 RANGE 硬门槛

单个窗口必须同时满足：

- 有效穿越 VWAP 至少 2 次；
- 高于 VWAP 与低于 VWAP 各停留至少 2 分钟；
- 单侧比例不高于 70%；
- 路径效率 ER 不高于 0.30；
- 20 分钟 VWAP 相对斜率绝对值不高于 0.10%。

有效穿越使用 VWAP 两侧 0.02% 中性带，只有从中性带一侧移动到另一侧才计数。连续 3 个窗口满足全部硬门槛后确认 `RANGE`。

### 6.3 趋势硬门槛

单个窗口必须同时满足：

- ER 不低于 0.55；
- VWAP 相对斜率绝对值不低于 0.10%，且与价格方向一致；
- 同方向单侧比例不低于 80%；
- 后半窗口高点和低点同时相对前半窗口按同一方向推进。

连续 2 个窗口方向一致才确认 `UPTREND` 或 `DOWNTREND`。任何指标冲突、确认不足或同时不满足两类硬门槛时均为 `UNCERTAIN`。

输出指标包括 `path_efficiency`、`one_side_ratio`、`vwap_crossings`、`vwap_slope`、`above_vwap_count`、`below_vwap_count`、`range_confirmation_count`、`trend_confirmation_count` 和逐项判定原因。

## 7. 做T候选门控

唯一方向性输出是 `BUY_CANDIDATE` 与 `SELL_CANDIDATE`。候选必须同时满足：

1. 行情健康为 `REALTIME`。
2. 决策点是最新已完成分钟。
3. 状态是连续确认的 `RANGE`。
4. 白黄偏离不少于 3 格。
5. 价格离昨收不少于 5 格。
6. 当前与上一完成分钟位于 VWAP 同一侧，且偏离绝对值开始收窄。
7. 以回归 VWAP 估算的毛差价覆盖买卖佣金与双边滑点。
8. 未触发五格快速上冲等风险屏蔽条件。

默认成本参数沿用当前项目：买佣金 0.012%、卖佣金 0.012%、单边滑点 0.10%、最低佣金 0 元；全部集中在配置常量中。候选返回 `expected_gross_edge_pct`、`round_trip_cost_pct`、`expected_net_edge_pct` 与 `blocked_reasons`。

偏离达到阈值但门控未全部通过时，输出 `DEVIATION_OBSERVE`，页面只显示“偏离观察”；其他情况输出 `WAIT`。页面和事件历史不得再出现“黄金窗口”“回补提醒”或“减仓提醒”。策略版本升级，旧提醒不参与新策略统计。

## 8. 做T回测

### 8.1 初始账户与基准

每个标的使用首个有效完成分钟价格，将 15,000 元目标底仓向下折算到整手。T 仓上限默认为底仓的 20%，再向下取整到整手。策略账户和基准账户拥有相同底仓以及同额 T 仓备用现金；基准账户全程不操作。

标的可在监控配置中覆盖 `base_notional_cny`、`base_shares`、`t_capacity_ratio` 或 `t_capacity_shares`，显式份额优先于金额和比例。

### 8.2 库存分类

账户独立记录：

- `overnight_sellable_shares`：昨日结转、当日可卖库存；
- `today_bought_shares`：当日买入、T+1 标的当日不可卖库存；
- `cash`：可用现金；
- `open_leg`：尚未配对的买入腿或卖出腿；
- `used_t_capacity_shares`：当前占用的 T 仓额度。

高抛后回补先卖出 `overnight_sellable_shares`，再买回相同份额。低吸后卖出先形成 `today_bought_shares`，后续经济配对的卖出必须来自 `overnight_sellable_shares`。T+1 标的绝不从 `today_bought_shares` 扣减可卖份额；允许当日回转的标的才可使用当日买入库存。

### 8.3 成交模型

- 信号在下一个已完成分钟成交，执行方式为 `NEXT_COMPLETED_BAR`。
- 每笔数量必须是 `lot_size` 的整数倍且不超过剩余 T 仓。
- 分钟成交量为零时不成交。
- 默认最多参与该分钟可换算份额的 10%，再向下取整到整手。
- 买入成交价增加单边滑点，卖出成交价扣减单边滑点；分别计算佣金。
- 现金、库存或流动性不足时记录明确的拒绝原因，不伪造成交。

### 8.4 配对与结果

每一对记录开腿、平腿、方向、份额、毛差价、佣金、滑点和净收益。收盘时不强制伪造成交；未完成买入腿、未完成卖出腿分别保留并按期末价计价。未完成卖出腿的卖飞损失定义为：期末按相同份额回补所需净成本减去实际卖出净收入，最小为零。

结果至少包括：完成配对数、胜率、配对净收益、未完成腿数量、卖飞损失、全部交易成本、未成交原因、期末总库存、期末可卖库存、期末当日买入库存、策略期末权益、基准期末权益、做T净增益和净增益率。

零交易或只有未完成腿时显示 `NO_COMPLETED_PAIRS` 或 `OPEN_LEG`，不得因为基准价格下跌而宣称策略跑赢。

新增 `/api/t-backtest` 返回真实做T回测。旧择时算法只保留为不评价收益的 `/api/signal-replay`，页面称“信号粗回放”。`/api/backtest` 暂时作为 `/api/t-backtest` 的兼容别名并返回弃用标识。

## 9. Web 与增量数据

- `/api/snapshot`：只返回各标的最新摘要、健康状态、状态指标、候选与 revision，不返回整日分钟数组。
- `/api/quotes?symbol=...&since=...`：返回指定标的当日新增或修订分钟。
- `/api/history/quotes`：按日期和标的读取历史，保持按需访问。
- SSE：首次连接发送轻量摘要，此后只发送 revision 后发生变化的摘要和分钟 upsert；支持 `Last-Event-ID`。

页面只在切换标的或收到该标的 revision 时拉取增量。估值详情继续按标的懒加载，不进入 SSE。

图表增加时间轴、价格轴、tooltip、价格线、VWAP、昨收、三格和五格阈值、候选成交标记。详情卡展示全部状态指标、确认次数、预期毛差价、双边成本、预期净差价和屏蔽原因。新增标的使用 `0.002`，表单同步显示三格 0.60%、五格 1.00%。

2026-08-28 的收盘后 `quotes.json` 含六只标的各 241 个完整分钟点，作为一次性重建输入。迁移过程先执行全部校验，再生成 schema v3 历史；污染的旧 `quotes.jsonl`、按日副本和旧提醒不进入新目录。若重建源校验失败，迁移整体失败且不产生半成品。

## 11. 错误处理

- 采集失败：保留最后有效行情用于观察，发布 `OUTAGE`，撤销候选，并记录原始错误。
- 单标的数据校验失败：本轮六只标的整体不发布，避免部分更新造成跨标的不一致。
- 历史原子写入失败：保留旧文件，不发布依赖未持久化数据的新 revision。
- SSE 客户端落后：按 revision 补增量；缓存已淘汰时要求客户端重新获取轻量快照与当日分钟。
- 回测遇到坏数据：该标的返回 `INVALID_DATA` 与原因，不使用其他标的数据替代。
- 估值或指数元数据缺失：保持现有只读降级，不阻断行情监控。

## 12. 测试与验收

测试使用标准库 `unittest` 和小型确定性夹具。测试脚本优先使用可用 `python`，再尝试 Windows Launcher 的任意 Python 3，不再硬编码 3.14。

必须覆盖：

- 当前分钟不进入历史，完成后进入，晚到最终值可 upsert；
- 昨收不一致、越过涨跌幅、OHLC 错误、量价矛盾被拒绝；
- 上午、午休、下午、跨日与缺分钟窗口隔离；
- 100% 位于 VWAP 同侧的窗口不能成为 `RANGE`；
- `UNCERTAIN`、`DELAYED`、`OUTAGE`、偏离扩大和成本不足均不能产生候选；
- RANGE 连续 3 窗口与趋势连续 2 窗口确认；
- T+1 当日买入不可卖、两种配对方式、T 仓上限与整手；
- 零成交、成交量参与上限、现金不足、库存不足、滑点和佣金；
- 未完成腿和卖飞损失；
- 策略与相同底仓基准的净增益；
- `/api/snapshot` 不含整日 points、分钟增量 upsert 与 SSE revision；
- 页面不含“黄金窗口”，并展示候选、健康状态、指标、轴线和 tooltip。

验收时先运行全套单元测试，再对重建历史执行审计：六只标的昨收各自唯一、主键唯一、schema v3 字段完整、510300 的 09:30 真实价为 4.684，并且任何历史记录都不包含 4.095 的模拟昨收。最后启动本地服务，验证摘要载荷大小、SSE 增量、断流撤销候选和页面交互。
